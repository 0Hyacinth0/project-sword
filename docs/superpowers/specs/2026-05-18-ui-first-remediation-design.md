# UI 优先前端整改第 1 里程碑设计

## 背景

项目当前已经具备登录、角色、背包、装备、战宠、地图、副本、战斗、社交、排行榜、竞技场、PVP 和测试页等前端模块，但整体体验仍存在三类问题：

- 设计落地不完整：部分页面和业务组件没有统一使用 `DESIGN.md` 的 Liquid Glass 视觉语言与 `src/components/ui` 通用组件。
- 交互状态不完整：加载、空状态、错误状态、禁用状态、危险确认和成功反馈覆盖不均匀，部分模块仍使用 `alert(...)`。
- 主流程体验不连贯：角色、背包、装备、战宠、战斗奖励、PVP 结算等状态更新分散，容易出现界面局部刷新但整体信息不同步的问题。

用户选择的总体路线是 **UI 优先**：先把可见界面做完整、统一、可演示，再进入稳定化和架构解耦。三个总阶段仍然保留：A 稳定性、B 体验还原、C 系统重整；本规格覆盖 C 版本路线下的第 1 里程碑，即 UI 还原基线。

## 目标

第 1 里程碑的目标是让当前已有前端页面达到“可演示、观感统一、状态完整”的基线：

- 登录、角色选择、角色创建、主页三栏、角色详情、背包、装备、战宠、地图、副本、战斗、好友、聊天、组队、排行、竞技场、测试页都具备完整 UI 状态。
- 所有主要视觉实现严格参考 `DESIGN.md`，复用 `variables.css` 中的颜色、字体、阴影、玻璃效果、圆角、间距和动画变量。
- 优先复用 `src/components/ui` 中的 `UiPanel`、`UiTabs`、`UiButton`、`UiIconButton`、`UiModal`、`UiToastHost`、`UiBadge`、`UiStatBar`。
- `npm run build` 恢复通过，确保后续 UI 迭代可以持续验收。
- Mock 模式下主要入口可以顺畅展示，不出现明显半成品、错位、无反馈或不可理解的空白状态。

## 非目标

本里程碑只做前端整改，不生成后端代码、数据库脚本或服务器配置。

本里程碑不重写游戏核心数值系统，不改变 `开发方案.md` 中的玩法设定，不重新设计职业、装备、战宠、战斗、PVP 规则。

本里程碑不强行完成所有架构解耦。对于明显阻塞 UI 状态一致性的耦合点，可以做局部收束；大规模 store/API/类型重整放到后续系统解耦里程碑。

## 页面与组件结构

### 页面壳

页面壳负责整体布局、路由级状态和跨面板协调：

- `LoginView.vue`：登录/注册入口，负责认证表单、认证反馈、Mock/真实接口提示。
- `CharacterSelectView.vue`：角色槽位选择，负责 3 槽位展示、空槽位引导、删除确认和进入游戏。
- `CharacterCreateView.vue`：角色创建，负责职业切换、雷达图、取名、属性预览和开始冒险。
- `HomeView.vue`：游戏主界面壳，负责顶部通栏、左中右三栏、中栏视图切换、底部快捷导航、跨面板刷新。
- `TestView.vue`：测试控制台，负责模块列表、测试结果、请求/响应日志和运行状态展示。

### 主页结构

`HomeView.vue` 在 UI 优先阶段保留现有三栏结构，但按职责收束：

- `GameHeader` 区域：品牌、公告、主题切换、退出登录。
- 左栏：`CharacterPanel`，包含属性、装备、战宠三个标签。
- 中栏：`MainStage` 概念区，承载首页、地图、副本、战斗、好友、聊天、组队、排行、竞技场。
- 右栏：`InventoryPanel` 概念区，承载背包标签、搜索、筛选、排序、网格、详情弹窗。
- 底部导航：地图、聊天、好友、组队、排行、竞技、商店占位。

`HomeView.vue` 可以继续作为文件存在，但内部应减少业务细节堆叠。对于样式和交互复杂的区域，优先下沉到已存在的功能面板或新增前端组件。

### 功能面板

每个功能面板都要具备一致的体验结构：

- 标题或上下文说明。
- 主操作按钮或明确的下一步入口。
- 加载状态。
- 空状态。
- 错误状态。
- 禁用状态。
- 成功/失败反馈。
- 移动端可读布局。

适用范围包括角色属性、装备纸娃娃、背包网格、战宠列表与详情、地图、副本、战斗控制台、好友、聊天、组队、排行榜、竞技场和 PVP 匹配。

### 通用 UI 组件

业务组件不再各自发明按钮、标签、弹窗和提示样式：

- 普通操作按钮使用 `UiButton`。
- 图标按钮使用 `UiIconButton`。
- 面板容器使用 `UiPanel`。
- 标签切换使用 `UiTabs`。
- 确认弹窗使用 `UiModal`。
- 成功/错误/信息反馈使用 `UiToastHost`。
- 状态徽章使用 `UiBadge`。
- HP、MP、EXP 等条形状态使用 `UiStatBar`。

如果某个现有业务组件确实需要新增通用状态块，应优先做成前端通用组件，例如统一的面板空状态或错误提示，而不是复制粘贴多份样式。

## 数据流与交互状态

UI 优先阶段要求界面状态有明确来源和刷新时机。

### 状态职责

- `View`：页面布局、当前视图、跨面板协调。
- `Panel`：局部选择项、弹窗开关、临时表单、局部交互。
- `Store`：业务数据、加载状态、错误状态和动作状态。
- `API`：Mock/真实接口分流、响应格式适配。
- `Config`：职业、装备、词条、强化、套装、地图、战宠、PVP 等静态规则。

### 核心联动

角色与背包联动：

- 使用消耗品后刷新背包和角色详情。
- 穿戴装备后刷新角色装备和背包。
- 卸下装备后刷新角色装备和背包。
- 强化装备后刷新角色装备，并根据材料消耗刷新背包。

战宠与角色联动：

- 设置出战战宠后刷新战宠列表。
- 喂食、进化、重命名、技能装备/卸下、战宠装备穿脱后刷新战宠列表。
- 出战战宠影响角色属性面板展示，属性面板读取当前出战战宠并呈现主人加成。

战斗与奖励联动：

- 战斗结束后在 Mock 模式写入奖励。
- 经验奖励刷新角色等级和经验。
- 物品奖励刷新背包。
- PVP 战斗返回竞技场时触发结算反馈。

### 反馈规则

- 成功、失败、信息提示统一使用 `UiToastHost`。
- 删除、丢弃、危险操作使用 `UiModal` 确认。
- 加载中的按钮使用 `loading` 和 `disabled`，避免重复提交。
- 网络或业务错误要显示在对应面板中，同时可以触发 Toast。
- 逐步替换现有 `alert(...)`，避免浏览器原生弹窗破坏设计一致性。

## 视觉与响应式规范

所有 UI 修改必须遵守 `DESIGN.md`：

- 背景、面板、按钮、输入框、弹窗、Toast 使用 Liquid Glass 风格。
- 色彩只使用 `variables.css` 中已有设计变量和 `DESIGN.md` 定义的语义色。
- 字体使用 `--font-display` 和 `--font-text`。
- 间距优先使用 4、8、12、16、20、24、28、32px 体系。
- 按钮和输入框圆角为 8px，面板圆角为 16px 到 20px，胶囊元素使用 980px。
- 桌面端保持三栏信息密度；中屏和移动端自然堆叠。
- 移动端不得遮挡主操作，不出现文字溢出、按钮拥挤或面板互相覆盖。

## 错误处理与测试验收

### 构建验收

`npm run build` 必须通过。当前已发现测试相关 TypeScript 构建阻塞：`src/testing/suites/authTests.ts` 调用了未导入的 `clearAuthState`。该问题属于 UI 优先阶段的前置修复，因为无法构建就无法持续验收界面。

### 测试页验收

`TestView.vue` 保留为前端测试控制台，并需要具备：

- 模块列表和当前选中模块。
- 单模块运行和全部运行。
- 运行中、通过、失败、跳过状态。
- 请求、响应、错误日志。
- 失败原因可读展示。
- 测试结束后清理拦截器和认证状态，避免污染后续手动演示。

### 页面验收

核心页面逐个检查：

- 登录和注册表单有加载、禁用、错误和成功反馈。
- 角色选择页已有角色、空槽位、满槽位、删除确认状态完整。
- 角色创建页职业切换、雷达图、取名、提交状态完整。
- 主页三栏在桌面和移动端均可读。
- 背包搜索、筛选、排序、空状态、详情弹窗和操作反馈完整。
- 装备纸娃娃、强化材料不足、卸下、套装展示状态完整。
- 战宠列表、详情、出战、喂食、进化、技能、装备状态完整。
- 地图、副本、战斗、社交、排行、竞技场入口不出现半成品状态。

## 里程碑完成定义

第 1 里程碑完成时应满足：

1. `npm run build` 通过。
2. Mock 模式下可演示登录、选角、主页、背包、装备、战宠、地图、副本、战斗、社交、排行、竞技场、PVP 的主要入口。
3. 核心页面和面板均有加载、空状态、错误状态、禁用状态和成功反馈。
4. 主要业务操作不再依赖浏览器 `alert(...)` 作为唯一反馈。
5. 桌面和移动端布局不出现明显遮挡、错位、文字溢出。
6. 新增或修改的前端函数保留函数级注释，说明作用、参数和返回值。

## 后续里程碑

第 1 里程碑完成后，进入体验稳定化：

- 扩展测试页覆盖主流程。
- 收束 Mock 数据刷新策略。
- 清理状态不同步和入口断流。

随后进入系统解耦：

- 拆分过重的页面壳。
- 统一 store/API/action 状态命名。
- 整理装备、战宠、战斗、地图、社交、PVP 的边界。
- 将重复的 UI 状态抽成通用前端组件。
